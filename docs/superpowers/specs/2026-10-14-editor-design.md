# nextcloud-plantuml — the editor

The **Edit diagram** overlay is a PlantUML source editor next to a live diagram. It grew in
small rounds on 2026-10-14 from Dr K using it. This spec collects each requirement in one
place, so none of the details from those rounds gets lost: a reader should be able to rebuild
the editor's behaviour from it alone. It sits beside the app spec
(`2026-10-13-nextcloud-plantuml-design.md`), which still covers the server side, the routes
and the Files integration.

The standing goal: **use what Nextcloud and CodeMirror already provide** before writing
anything by hand.

## Requirements

Status: **shipped** (with its PRs), **building** (on a branch), **agreed** (approved by Dr K,
not yet built; the round that builds it is named), or **proposed** (an idea Dr K raised or was
offered, not yet agreed). Every colour below is a Nextcloud variable; a
"pulled toward the text" colour is `color-mix(in srgb, var(<variable>) 75%, var(--color-main-text))`
unless a share is given.

### Saving

| # | Requirement | Source | Status |
|---|---|---|---|
| S1 | Save on Ctrl/Cmd+S (never the browser's "Save page as") or a click on the indicator: a WebDAV `PUT` with `If-Match` and the ETag last read or written. The new ETag comes from the PUT's `ETag` header, else `OC-ETag`; an answer with neither is an error, never a conflict, so the next save never sends `If-Match: null`. | design | shipped (#4) |
| S2 | Autosave 2 s after the last change, and at most 30 s after the first unsaved one; each autosave starts a new 30 s window. | Dr K: "auto save … after some inactivity" | shipped (#21) |
| S3 | Text's indicator: one flat icon button labelled "Save". A check means saved; a check with an 8 px primary dot (ringed in the background colour) means unsaved; core's `icon-loading-small` spinner in place of the check means saving. Its `title` reads "Saved" before this editor has written anything, then "Saved just now" under a minute, "Saved N min ago" under an hour, "Saved N h ago" after, refreshed every 30 s; while unsaved or saving it reads "Unsaved changes". A click saves now. | Dr K, after Text | shipped (#21) |
| S4 | Close (the × or Escape, K1) saves first, then closes. It keeps saving until the file holds the source, a change typed meanwhile included, waiting out any operation in flight. If that save is refused (412), the editor stays open on the conflict line. If it fails, or 10 s pass with a save hanging, it asks "Discard unsaved changes?"; Cancel stays open. A close after a failed or refused save asks at once, without saving again. Once closed, nothing more is ever sent: the watcher, the timers and any waiting render stop, and a hanging save that settles later writes nothing more. | review | shipped (#21) |
| S5 | Leaving the page with unsaved changes gets the browser's own prompt (`beforeunload`). | design | shipped (#21) |
| S6 | Someone else's change (412) stops autosave and shows "Someone else changed this file", which stays as the source changes, with **Reload** and **Save as copy**. While it lasts, Save, Ctrl/Cmd+S and autosave write nothing and the watcher looks no more; only Reload or Save as copy ends it. Reload asks "Replace your changes with the saved file?" when anything is unsaved, then takes the file and its ETag. | design | shipped (#4, #15) |
| S7 | A new diagram's `@startuml`/`@enduml` come from the server (`NewDiagramListener` on Files' create endpoint), so a click and an API call make the same file. On S3 object storage a new file is one space, which counts as blank. | Dr K: "Shouldn't the backend do that?" | shipped (#18, #19) |
| S8 | **Save as copy** writes the source to `<name> (copy).<ext>` beside the file, else `(copy 2)` up to `(copy 9)`, each with `If-None-Match: *` so a taken name answers 412 and is never overwritten; after `(copy 9)` it gives up. The copy is announced to Files (`files:node:created`), and the editor carries on in it: the title, the overlay's and the diagram's names, V2's file name and the ETag all become the copy's. A copy that fails, for that or any reason, says "Could not save a copy" and keeps both buttons; if only reading the copy back fails, the copy exists all the same. | design | shipped (#15) |
| S9 | One file operation at a time (save, Reload, Save as copy, a watcher check). An operation asked for while another (not a check) runs is dropped, and a change left unsaved is autosaved 2 s after that one ends. A check gives way: it is skipped while anything runs, and anything else waits it out. A check shows no spinner; any other operation shows the spinner and disables Reload, Save as copy and the Reload icon (the icon without dimming, so autosave never makes it flicker). | review | shipped (#21, #28) |
| S10 | A save that fails for any reason but a 412 says "Could not save the file" and stops autosave until the next change, which clears the line and tries again. A failed Reload says "Could not open the file". Each is also logged with `console.error`. | design | shipped (#4, #21) |

### Changes made elsewhere

| # | Requirement | Source | Status |
|---|---|---|---|
| E1 | The editor notices when the file changed elsewhere (VS Code over WebDAV, another browser) without closing. A check is a `PROPFIND` for `getetag` alone (the quotes the client strips are put back). It runs every 10 s while the page is visible, at once when the page is shown again (`visibilitychange`) or the window gets the focus back, and never while the page is hidden. With `@nextcloud/notify_push` available, every `notify_file` push (any change to the user's files; it names no file) runs a check and the clock slows to once a minute; `listen()` is asked once per page. Two checks never overlap: one asked for meanwhile runs once after. A failed check goes to `console.debug` only, and the bar says nothing. | Dr K | shipped (#28) |
| E2 | A matching ETag, our own save's included, is no change. A clean editor then reads the file and replaces only the stretch that differs, so the cursor and the scroll position stay; the change is kept out of the undo history, the indicator's "Saved …" keeps our last save, and when the text differed the bar says "Updated from the file" until the next change. A dirty editor, or one typed into while the file loaded, goes into the S6 conflict state. No check runs while closing or in a conflict. | Dr K | shipped (#28) |
| E3 | A Reload icon (refresh, labelled and titled "Reload from the file") that is always in the bar, not only in a conflict. It asks "Replace your changes with the saved file?" first when anything is unsaved, and is otherwise S6's Reload. Unlike E2's take-in, a Reload is an ordinary edit in the undo history. | Dr K | shipped (#28) |
| E4 | Every read of the file sends `Cache-Control: no-cache`. Nextcloud sends no `Cache-Control` with a file, so a browser may answer from its cache for a tenth of the file's age and a changed file reads back stale. | live check | shipped (#29) |

| # | Requirement | Source | Status |
|---|---|---|---|
| H1 | Every colour comes from Nextcloud's theme variables, so light, dark and high contrast all work. No literals: `tests/js/theme.test.js` fails on any hex, `rgb()`, `hsl()`, `white` or `black` in the highlight style or the surface rules. | Dr K (black on black) | shipped (#18, #20) |
| H2 | The mode is a `simple-mode` table ported from Prism's `plant-uml` grammar (v1.30.0, MIT). | H8 | Creole is highlighted where PlantUML reads text: a link's label; a note after its colon, or from `note`/`hnote`/`rnote` alone on its line down to `end note` (`endnote`, `end hnote`, `endrnote`); a legend down to `end legend`; a `[ … ]` description from a line ending in `[` to a line starting with `]`; `title`, `header` or `footer` alone on its line down to its `end …`; and `title`, `header`, `footer` or `caption` with text, on that line. ### Styling dictionary

Researched on 2026-10-15: Lezer's tag set (`@lezer/highlight` 1.2.5, read from the module), the
TextMate/Sublime scope names, Neovim's tree-sitter captures, LSP 3.17's semantic tokens and
Pygments' token types, against the theme files of VS Code Light+/Dark+, GitHub, One Dark Pro,
Solarized, JetBrains, Catppuccin and Dracula; UML 2.5.1 for stereotypes; and the lexical forms of
all 30 diagram types in PlantUML 1.2026.8's source.

Every grammar names what it reads with one category of this list, and the theme gives each
category one look, so the same kind of thing looks the same in every diagram type. A category
is a Lezer tag, written as the token string `StreamLanguage` resolves (`logicOperator`,
`variableName.function`), or one of the editor's own tags, each defined under a Lezer parent
(`Tag.define(parent)`), so a category with no look of its own takes its parent's. The grammars
may tell more apart than the theme shows: no theme colours arithmetic, comparison and logical
operators apart, and none colours brackets by shape, so those differ by weight or not at all,
and a later theme can still tell them apart. No category adds a colour: every look is one of
the palette's above.

### Preprocessor, styles and the server's vocabulary

Researched on 2026-10-15 against the live server (PlantUML 1.2026.8), plantuml.com and
PlantUML's source at that version. Facts: the server's `help keywords` lists **30**
`@start…` types (C2 offers 9 today) and 136 other keywords; `help types` lists **53** element
types. The preprocessor's own grammar (`TLineType`) has these directives: `!define`,
`!definelong`/`!enddefinelong` (legacy), `!undef`, `!$name = …` (with `?=`, and `!local`/
`!global`), `!assert`, `!if`/`!ifdef`/`!ifndef`/`!elseif`/`!else`/`!endif`, `!while`/
`!endwhile`, `!foreach`/`!endfor`, `!function`/`!procedure` (optionally `!unquoted`, `!final`)
… `!endfunction`/`!endprocedure`, `!return`, `!theme`, `!include`/`!includeurl`/
`!include_many`/`!include_once`, `!includedef`, `!includesub`, `!startsub`/`!endsub`,
`!import`, `!log`, `!dump_memory` and `!option`; `!pragma` is a command of its own. Built-in
functions start with `%` (about 80 in the source; 47 documented, with descriptions, in its
`tim/builtin/readme.md`). `!pragma` takes the keys of `PragmaKey` (`aspect`, `compact`,
`default_label_angle`, `default_label_distance`, `edge_corner_radius`, `graph_attributes`,
`horizontal_line_between_different_package_allowed`, `kermor`, `label_angle`,
`label_distance`, `ratio`, `sequence_message_span`, `show_deprecation`, `svg_font`,
`svg_interactive`, `svg_parser`, `svek_trace`, `teoz`, `tex_system`, `tex_preamble`,
`use_intermediate_packages`, `use_vertical_if`; matched ignoring case and `_`, so
`useVerticalIf` works), plus `layout` (`smetana`, `elk`, `vizjs`) and `svgSize`.
`skinparam` is deprecated: plantuml.com/skinparam says it "is being phased out" in favour of
`<style>`. A style block is `<style>` … `</style>`, or `<style>…</style>` on one line, or
`<style file=…>` (no other tag starts a line); inside it, selectors (`root`, the 157 names of
PlantUML's `SName`: diagram types such as `mindmapDiagram`, elements such as `node`, `arrow`,
`note`; `.stereotype` classes; `:depth(n)`; `*`) and the 30 properties of `PName`
(`BackGroundColor`, `FontColor`, `FontName`, `FontSize`, `FontStyle`, `FontWeight`,
`LineColor`, `LineThickness`, `LineStyle`, `RoundCorner`, `DiagonalCorner`, `Shadowing`,
`Padding`, `Margin`, `MaximumWidth`, `MinimumWidth`, `HorizontalAlignment`, `HyperLinkColor`,
`HyperlinkUnderlineStyle`, `HyperlinkUnderlineThickness`, `HeadColor`, `ExportedName`,
`Image`, `ImagePosition`, `ShowStereotype`, `MarkerShape`, `MarkerSize`, `MarkerColor`,
`BarWidth`, `Width`). The stdlib holds 33 libraries (the server's `stdlib` command) and about
29,000 includable files in `plantuml/plantuml-stdlib`, whose folder names match; includes are
case-insensitive (`<c4/…>` and `<C4/…>` both work).

## Known limitations

Each checked against the code on 2026-10-14.

- **No WebDAV request has a timeout.** A hung `PROPFIND` or `GET` in a check holds every Save, Reload and Save as copy behind it (S9); close still exits through its 10 s prompt (S4).
- **notify_push costs ~20.6 kB gzip** (it brings axios) in the editor bundle, while the live instance has no notify_push app. Keeping or dropping it is Dr K's call.
- **Links inside the diagram are keyboard-focusable but hidden from screen readers,** since the container is one `role="img"`.
- **The Viewer and the README still show diagrams as `<img>`,** so their links do not work there.
- **Colour picker:** a pick drops the alpha of `#RRGGBBAA`/`#RGBA`.
- **Creole `--strike--` and `~~wave~~` are not highlighted** (they collide with links, H8).
- **A profile chunk whose fetch failed stays failed until the page reloads.** Browsers keep a failed module fetch per page, and `import()` paths are fixed at build time (P4).
- **A block left open after the last closed one has no image** and its tab reads "not a PlantUML server" (B5); B7 marks the block.
- **PlantUML's YAML is more lenient than the strict YAML the lint checks:** `profile: INTERNET : [oops` draws, the lint marks it.
- **A YAML error at the very end of a line is a zero-width mark.**
- **Inside a yaml block, `/' '/` and `<style>` lines are coloured by the YAML grammar,** though the lint skips them.
- **The editor bundle carries the whole WebDAV client** (`webdav`, `axios`, `semver`, through `@nextcloud/files/dav`) for one GET, one PROPFIND and two PUTs. Not part of the diagram-types rounds; a candidate for its own.
- **The first `<:` of a day waits ~9 s** while the server reads every emoji block (C7).
- **`<<stereotype>>`:** the first `<` briefly opens the tag popup, which the second closes.
- **Penpot boards for the style editor are not drawn yet:** the Penpot plugin was unreachable during the style round.
- **Includes inside a false `!if` branch or a block comment are resolved,** since the resolver cannot evaluate the preprocessor; a rare false "Cannot find" in a branch nobody uses.
- **A shared diagram's relative includes resolve in the viewer's own files** (R1's caller's-rights rule): a deliberate share can show the viewer's own file in the viewer's render.
- **README fence renders are cached for the page,** so an edited include shows there after a reload.
- **A Latin-1 byte in a server error shows escaped** (`%XX`), because `decodeURIComponent` fails; PlantUML's headers are ASCII in practice.
- **An element named `colors` or `help` gets no connector list** after it (the helper-command names, X13, stop the connector context).
- **A `$tag` after an element** (a UML tag that `hide`/`show` select) is coloured as a preprocessor variable: the preprocessor expands it when one of that name is defined, so the editor cannot tell the two apart.
- **A `<style>` left open inside a block that has no `@end` delays the next `@start` until `</style>`.**
- **Core completion sources run per keystroke over the whole document;** measured about 3 ms on 3,600 lines.
- **Behat cannot see highlighting, layout, the picker or the watcher;** those rest on unit tests and live checks.

## Traps found in the live instance

- **Asset caching.** App scripts and styles are cached for six months under `?v=`, which changes only with an app version. The lazy editor URL carries `&h=<build hash>` (O2). Page-load bundles and CSS need one hard refresh after a hand deploy.
- **Route caching.** The route table lives in APCu in the web server. A new route can answer 404 long after the 3600 s TTL. `apachectl -k graceful` fixes it.
- **Object storage.** S3 writes a space for an empty file (S7). In CI, on local storage, two writes in the same second can keep the same ETag, so a conflict test stamps `X-OC-Mtime`.
- **DAV GET caching.** A file comes with no `Cache-Control`, so the browser caches it heuristically; the editor sends `no-cache` (E4).
- **Core and other apps reach into the editor.** Core's `server.css` styles every `div[contenteditable]` as an input, and `files_bpm` forces it black (H7). Core's button rules outrank a single class, so the bar's buttons are styled as `button.<class>` and the search panel's as `& .cm-panel.cm-search …`. Core's input rules give the picker's `<input type="color">` a margin and a 30 px height (C6). Core styles every `a`, which the diagram's links undo (D5).
- **CodeMirror's own colours assume a white page.** Its base theme, `defaultHighlightStyle` and the lint underline SVG all hard-code colours, so each is overridden with variables (H1, V1).
- **Driving the browser.** A selenium key press must target `.cm-content`. A bare Enter reaches Files underneath and opens the Viewer.

- **Style round.** New under `tests/js`: `style-profile.test.js` (the style grammar, completion and checks), `values.test.js` (the value registry, choosers and steppers) and `vocabulary.test.js` (the generated vocabulary); the colour, `%`, Creole, files and include-path cases sit in `completion.test.js`, `plantuml-mode.test.js` and `lint.test.js`. New under `tests/unit`: `IncludeResolverTest.php` (every include form, limits, cycles, zips, line maps) with `RenderControllerTest.php` and `RenderServiceTest.php` for the routes' `path`, ETag and `GET /colors`, and the fixtures `colors.svg` and `help-colors.txt`.
- **Behat.** Through the API only, never a browser; a scenario that truly needs one would be `@ui @blocked`, and none does. `features/diagrams/edit.feature` covers a changed source drawing, save, a refused save over someone else's change, Save as copy, the server's themes and a mistake naming its line; `create.feature` covers a new diagram.
- **Live checks.** Layout, colour, the picker and the watcher are checked in a clean selenium profile on both themes each round.

## Decisions

| Decision | Why |
|---|---|
| The editor is a lazily added bundle, its URL carrying a build hash | Most Files pages never open it; `?v=` alone kept a new build from the browser for months |
| Autosave on 2 s idle and 30 s max, after Text | Text saves a few seconds after typing, and Dr K asked for the same |
| Close saves first, and asks only when it cannot | Closing should never lose work, nor trap the user behind a read-only share, a full quota or an outage |
| Only Reload or Save as copy ends a conflict | A save over someone else's change could only be refused again; both ways out keep every version |
| The server writes a new diagram's `@startuml`/`@enduml` | Dr K: "Shouldn't the backend do that?"; a click and an API call make the same file |
| Poll first, `notify_push` when present | The live instance has no `notify_push`, and the client library says when push is unavailable |
| A take-in from elsewhere stays out of the undo history | Undoing it would be an edit of ours, which autosave would write back over theirs |
| A check never shows the spinner and gives way to the user | It runs every 10 s; it must not flicker the bar or delay a save |
| Every colour a Nextcloud variable, mixed with `color-mix()` | A hard-coded colour went black on black; status hues are pulled toward the text because their `-text` variants are near white on dark |
| Labels in violet, not a primary tint | The primary tint read near white on dark; violet is the one free hue (H4) |
| Creole lives in the PlantUML mode's own states | It is only Creole where PlantUML reads text (labels, notes, legends, titles), and a label must keep its violet under it |
| `--strike--` and `~~wave~~` stay plain | They collide with the links `--` and `~~`, which matter more |
| Existing libraries before hand-written code | Dr K: "check for existing libs to use"; hence the colour picker from `@uiw` and DOMPurify |
| Themes, icons and emoji come from the server, never a fixed list | The list follows the server's version; even the emoji blocks are the ones `emoji` names. C5 would do the same for skinparams |
| One file per completion source and per lint rule | Dr K asked for a pattern to grow |
| Draw the SVG inline, sanitised by a private DOMPurify | Dr K: "let's draw it inline with svg" so links work; an `<img>` loaded nothing, and the inline SVG must load nothing either |
| Fit the diagram by default | Dr K: "it should auto fit so it's always visible" |
| Always wrap long lines | Dr K: "let's just always wordwrap" |
| Diagrams in a file are tabs, linked both ways to the cursor | Dr K's design: the diagram follows the cursor, the cursor follows the tab |
| Only the active diagram is drawn | PlantUML draws one per request; drawing all of them on every keystroke multiplies the server's work for diagrams nobody is looking at |
| Folding and tabs come from our own block scanner | The stream mode has no syntax tree; one scanner serves tabs, folding, lint, rendering and profiles alike |
| CodeMirror's YAML, JSON and EBNF modes nested in ours | Maintained grammars before hand-written ones; a Lezer language cannot nest in a stream language, so the legacy modes are the ones that fit |
| A profile per type, loaded when the file holds it | Dr K: "load what it needs … prevent one super thing" |
| The editor becomes an ES module with hashed chunks | An IIFE cannot be split; the live CSP allows the chunks, and hashed names beat the six-month cache |
| JSON and YAML are checked in the editor | The server draws bad data as a picture with no error line, so nothing else would mark it |
| A Source toggle, `<>`, pressed while the source shows | Dr K: "a toggle for show/hide the code makes a bit more sense" |
| Stock fold keys, minus fold-all | Cmd-Shift-[ / ] switches tabs on macOS, and Ctrl-Alt-[ / ] are AltGr+8/9 on many layouts; the gutter and per-block keys remain (B6) |
| A profile is a factory `(core) => Profile` | The entry then has no static chunk import, so a failed chunk cannot take the editor down and B1 stays in the entry (P2) |
| The render index is PlantUML's, not the tab's | A file with an unclosed block draws differently from its tab order; `render` follows what the live server does (B1, B5) |
| The YAML lint reports every error, to the end of the line | T11 says its errors; a one-character mark was easy to miss |
| Vocabulary from the server first, else generated from PlantUML's source at the server's version | A hand list drifts (C2 offered 9 of the server's 30 diagram types); the server's own `help` answers are always right for it, and the source is the authority for what the server cannot list |
| The stdlib index ships with the app, per library | 29,000 paths are too many to send at once and the server cannot list them; a per-library file is small, and nothing leaves the Nextcloud server |
| `<style>` before `skinparam` | plantuml.com: `skinparam` "is being phased out" |
| Relative includes are expanded by the Nextcloud server | The PlantUML server cannot read Nextcloud's files and refuses local paths; the app already reads files with the caller's rights, so the same rules guard what an include can reach |
| Choosers and steppers on the cursor's line only | Dr K wants VS Code's in-place pickers; drawn on every value they would bury the source, while swatches are few enough to stay |
| Profiles get `core.t` | A profile's messages must be translatable like every other string, and a profile imports no core module, so the translator comes in with `core` (P2) |
| Named colours in a style block are offered bare, `#` switching to hex | plantuml.com writes `BackgroundColor Red` there; a longer list after a `…Color` property is the cost |
| Mindmap and wbs put their node selectors before the diagram's own | `node`, `rootNode`, `leafNode`, `boxless`, `arrow` and `:depth(` are what a mindmap style block holds (plantuml.com/mindmap-diagram) |
| A library zip may be 8 MB on disk (16 MB for all), entries still 1 MB uncompressed | R7 counts uncompressed size, and a 1 MB on-disk cap would refuse icon libraries |
| Where the resolver has a mistake on a line, its message wins | It names the path and the limit, which the server's message for the same line cannot |
| A path or selector with `$` or `%` is left to the server | PlantUML expands it; the resolver cannot, so it makes no mistake of it |
| Includes resolve with the caller's rights | Nothing outside the caller's own files is ever read; a share they can open works (R1) |
| Behat through the API only | Dr K: "The behat tests should not need the browser"; "try not to have any `@ui` tags" |
| One dictionary of categories, each a Lezer tag | Dr K asked for one; the theme colours a category once, so a new grammar cannot invent a look, and Lezer's parent tags let a grammar tell apart more than the theme shows (Y, G1) |
| A lexicon in core, handed to profiles | DRY without breaking P2: a profile importing it would make it a chunk the entry imports statically (G2) |
| Stereotypes orange, in plain face | UML 2.5.1 puts them "in plain face within guillemets", italic and underline mean abstract and static there; orange pairs `<<x>>` with the `.x` selector that styles it (H13) |
| Assignment quiet, logic in bold | Dr K's softer `=` in a tag, made the rule; no theme splits operators by hue, so the slight difference is weight (H19) |
| Brackets in bold grey | Every hue already names a category, so colouring brackets by depth would collide with them (H20) |
| Only what a line declares is moss | Colouring every use of a name would bury the text; a declaration is where a reader looks for one (H15) |
| The floor is PlantUML 1.2026.8 | Dr K; the source at that version is the authority, and plantuml.com sometimes runs ahead of it (G6) |
| What the server cannot draw is grey | Dr K: the source should show what the diagram pane will (T26) |
| A diagram's name is underlined, `title` is not | Dr K: the name after `@start<type>` is the diagram's own, one line and plain text, which nothing else on the line shows; `title` is Creole the drawing shows (H12) |
| Includes pick a block by index or id | plantuml.com documents `!N` and `!ID`; a bare name matched only the first word of a name with spaces, which PlantUML never did (R2, R8) |
| Creole colour tags take a bare name | The server draws `<back:#Red>` as text (W6) |
